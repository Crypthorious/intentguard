Rugwall (formerly IntentGuard)

Rug, price and copy-trade firewall for NEAR trading agents

An AI trading agent proposes a swap. Rugwall checks it for a rug-shaped token, a quote that is off the live pool price, a copied wallet with an insider track record, and the human's spending caps. Only then does it sign an ed25519 verdict. The NEAR contract stores the guard's public key and refuses any settle without a fresh, unused signature, so an agent that skips the guard can't settle, even inside its caps.

Add Rugwall to your agent

3 steps: ask the guard → get a signed verdict → settle with it

Give any MCP client (Claude Desktop, Cursor, an agent framework) a read-only pre-trade check. It runs the four checks on a real 1Click dry quote and the live Ref pool. It never signs.

{"mcpServers": {"rugwall": {
  "command": "python3",
  "args": ["/path/to/intentguard/mcp/rugwall_mcp.py"]
}}}

// then the agent calls, before every swap:
rugwall_check_swap {"amount_usd": 50}                                   → ALLOW + live quote vs pool
rugwall_check_swap {"amount_usd": 150, "copied_wallet": "insider_demo"} → DENY + 3 reasons
rugwall_policy     {"agent": "bot1"}                                    → live caps, kill switch, guard key

The guard process holds the verdict key, outside the agent and outside the repo. The agent only gets the signed verdict and passes it to settle.

from intentguard_guard import guard, verdict
from intentguard_guard.contract_testnet import ContractTestnet

contract = ContractTestnet("intentguard-5821c5.testnet", "guard2.intentguard-5821c5.testnet",
                           "~/.near-credentials/testnet/agent-keys/bot1.json")   # agent's settle-only key
signer = verdict.GuardSigner.from_key_file("~/.near-credentials/testnet/agent-keys/guard-verdict.json")
ctx = {"contract": contract, "treasury_usd": 1000, "signer": signer,
       "contract_id": "guard2.intentguard-5821c5.testnet"}

v = guard.evaluate(proposal, ctx)        # risk caps, rug check, quote vs pool, copied wallet
if v["allow"]:                           # ALLOW comes with an ed25519 verdict; DENY is never signed
    contract.settle(contract.agent_public_key(), v["amount_raw"], proposal["token_in"],
                    proposal["token_out"], v["intent_hash"], verdict=v["signed_verdict"])
else:
    print("blocked:", v["reasons"])

What actually reaches NEAR. The agent's function-call key can only call settle on this contract. Without a fresh, unused guard signature over these exact fields, the call fails.

near contract call-function as-transaction guard2.intentguard-5821c5.testnet settle \
  json-args '{"amount":"50000000","token_in":"<usdc>","token_out":"wrap.near",
    "intent_hash":"<sha256 hex>",
    "verdict":{"nonce":"<u64>","expires_at_ns":"<now + ≤10 min>","signature":"<128 hex chars>"}}' \
  prepaid-gas '30 Tgas' attached-deposit '0 NEAR' \
  sign-as guard2.intentguard-5821c5.testnet network-config testnet \
  sign-with-access-key-file agent-key.json send
# no verdict → ERR_NO_VERDICT · changed field → ERR_BAD_SIG · reused → ERR_REPLAY

What is real here

  • Real, on testnet: the Rust contract, its caps, the kill switch, the function-call key limited to settle, and on-chain ed25519 verification of every guard verdict, with replay and expiry protection.
  • Real, read-only, mainnet data: the 1Click quote (dry: true, so no deposit address and no funds), Ref Finance pool 4512 reserves, and the ft_metadata of USDC and wNEAR.
  • Fixtures: the two meme tokens (goodmeme.pump, rugmeme.pump) and the copied-wallet histories.
  • Saved, then re-checked live: the guard's verdicts come from the last live testnet run (the guard runs off-chain and its key never touches this page). The transactions behind them, the guard key and the nonce state are read from the chain while you watch.
  • Not done: settle records the spend and emits an event. It does not forward to intents.near or move tokens. There is one guard key, held by one guard process. No mainnet, no real money.
